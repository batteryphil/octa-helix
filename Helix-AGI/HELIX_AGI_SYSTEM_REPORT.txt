2.2 EXPERIENCE TUPLE COLLECTOR — QUALITY GATE (NEW)
------------------------------------------------------
File: training/self_trainer.py
Change: collect_experience() now applies strict quality filter.

Gate logic:
  tool_success  = tool_calls exist AND result has no error/traceback/failed
  novel_belief  = ctx.novel_belief_added == True
  significant   = fitness_delta > 0.05
  criteria_met  = sum([tool_success, novel_belief, significant])
  if criteria_met < 2: DISCARD (no write to disk)
  if criteria_met >= 2: ACCEPT (log + write)

Flush threshold: 50 → 10 (fewer, higher quality)
Log on accept: "[trainer] Quality tuple accepted: outcome=X quality=Y criteria=Z/3"

NOTE: The 50 pre-existing tuples in data/experience_tuples.jsonl were
collected under the old system (no gate). They are NOT automatically
deleted. However, _load_high_quality_examples() already gates on
outcome=="tool_executed" AND quality>0.7, so they will not be selected
for LoRA training unless they happen to meet those criteria (unlikely —
almost all are outcome="prose" quality=0.5).

Recommendation for reviewer: should we zero the file and start clean?
Risk: lose 50 data points. Benefit: clean slate, no confusion about
which tuples are quality-gated vs legacy.
