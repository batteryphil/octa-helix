SECTION 7 — DESIGN DECISIONS & RATIONALE
================================================================================

7.1 WHY LOCAL / NO API
-----------------------
  - Zero marginal cost per token — can run indefinitely
  - Data privacy — beliefs, reflections, experience never leave machine
  - Hardware ownership — no service dependency or rate limits
  - Research validity — closed environment, reproducible

7.2 WHY 4-BIT NF4 QUANTIZATION
---------------------------------
  - RTX 3060 has 12GB VRAM. Hermes-3 8B in fp16 = ~16GB → doesn't fit
  - NF4 = ~4.5GB for weights + ~1.8GB KV cache = fits with headroom
  - Quality tradeoff: NF4 loses ~1-2 perplexity points vs fp16
  - Acceptable for tool writing and reflection; would matter more for
    mathematical reasoning tasks

7.3 WHY HERMES-3 (not Llama-3 base, Mistral, etc.)
-----------------------------------------------------
  - Hermes-3 is instruction-tuned with strong tool-use formatting
  - Native JSON output compliance higher than base Llama-3
  - Strong self-reflection capability (constitutional AI alignment)
  - Hermes-3 has been pre-trained on agentic task formats

7.4 WHY MAMBA3 ARCHITECTURE IN OWNER'S OTHER REPOS
----------------------------------------------------
  - Owner is researching SSM (State Space Model) architectures
  - Mamba3 uses complex numbers for richer sequence modeling vs LSTM
  - Helix itself runs Hermes-3 (transformer), but the curiosity engine
    is directed to study Mamba3 repos for architectural inspiration
  - Long-term goal: apply Mamba3 insights to Helix's own architecture

7.5 WHY FITNESS-GATED REVERT INSTEAD OF UNIT TESTS
----------------------------------------------------
  - Agent writes arbitrary Python — can't write unit tests in advance
  - Fitness is a behavioral proxy: does the agent perform better overall?
  - Limitation: fitness is noisy (see Issue 7 above)
  - Alternative considered: run proposed code in sandbox first — not
    implemented due to complexity of sandboxing arbitrary tool code

7.6 WHY 10-CYCLE STRATEGIC REFLECTION
---------------------------------------
  - Too frequent: noise drowns signal, agent over-corrects
  - Too infrequent: agent pursues dead ends for too long
  - 10 cycles ≈ ~1.7 hours of operation — enough data to pattern-match
  - Reflection quality is high: agent correctly diagnoses issues each time
  - Problem: agent diagnoses correctly but doesn't successfully act on it
    (see Issue 1 and 6 above)
